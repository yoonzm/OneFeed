# OneFeed

[English](README.en.md) | 简体中文

[官方网站](https://onefeed.fyi/) · [隐私政策](https://onefeed.fyi/privacy/) · [问题反馈](https://github.com/yoonzm/OneFeed/issues)

> 把散落在不同平台的信息流，变成真正属于用户的阅读空间。

OneFeed 是一个面向 Web 信息流的浏览器扩展。

它尝试在微博、X、小红书、Reddit、知乎、Hacker News、Linux DO、V2EX、36Kr 等彼此割裂的平台之上，建立一层统一、安静、可控的阅读体验：内容仍然来自原来的世界，但如何呈现、如何筛选、如何沉淀，由用户决定。

## 为什么做 OneFeed

今天，我们每天阅读大量信息，却很少真正拥有自己的阅读体验。

不同平台决定界面、内容密度、推荐逻辑和注意力分配。为了阅读不同来源的内容，用户需要不断适应不同的产品规则，也越来越难从持续刷新的信息流中识别真正重要的东西。

OneFeed 希望改变这种关系。

我们相信，平台可以提供内容和社区，但不应该垄断阅读方式。阅读界面应当服务于理解，而不是争夺停留时长；算法应当接受用户的选择，而不是替用户决定什么值得关注。

## 愿景

OneFeed 的长期愿景，是成为跨平台信息流的通用入口和个人内容操作系统。

无论内容来自哪个网站，用户都应该拥有三种基本权利：

- **视觉表达权**：自由决定主题、布局、信息密度与阅读节奏；
- **内容筛选权**：按照自己的目标进行降噪、去重、摘要和排序；
- **信息控制权**：把真正有价值的内容留在自己的知识系统中，而不是困在平台里。

OneFeed 不想成为另一个封闭的内容平台。它希望成为用户与现有平台之间的一层个人界面：尊重内容来源，保留必要互动，同时把阅读和注意力的控制权交还给用户。

## 从统一阅读到个人信息空间

OneFeed 从统一不同网站的阅读体验开始，并将逐步探索：

- 覆盖更多内容平台与开放信息源；
- 允许用户选择和创造自己的阅读主题；
- 使用 AI 帮助摘要、降噪、去重和理解复杂内容；
- 让用户拥有自己的筛选规则与信息组织方式；
- 将阅读结果连接到 Notion、Obsidian 等个人知识系统；
- 建立开放的主题与扩展生态。

最终，我们希望每个人都能拥有一套真正属于自己的信息流：它跨越平台，理解偏好，尊重注意力，并长期服务于个人成长。

## 当前阶段

OneFeed 仍处于早期阶段，优先保证各平台基础信息流的稳定阅读链路。

- **当前支持**：微博热门首页、微博详情与内容检索、X 首页时间线、小红书发现页与笔记详情、Reddit 首页/排序页/社区信息流、知乎、Hacker News、Linux DO、V2EX，以及 36Kr 资讯频道与文章详情。

当前版本支持自定义阅读器顶部的网站显隐与顺序，并可分别关闭信息流列表和详情页中的内容图片；作者头像、网站标识与视频播放不受影响。页面右侧悬浮控件只保留一键暂停入口，阅读器 Header 右侧的设置按钮进入完整设置页。展示过滤规则仍在本地按已读状态、关键词、作者、平台和内容类型执行。富媒体平台只接管已明确支持且可稳定解析的 Feed 与详情路由，未支持的详情页、完整播放器和无法可靠代理的复杂互动仍回退原站。

X 适配登录后的 `/home` 时间线，支持“为你推荐”与“正在关注”频道，以及推文文本、图片、视频封面、外链预览和互动统计；推文详情页与缺少可靠永久链接的推广卡片暂不接管。

微博适配首页热门信息流、未登录时的热门首页、形如 `/<uid>/<mid>` 的单条微博详情，以及 `s.weibo.com/weibo` 内容检索结果；详情完整展示正文、图片、视频封面和互动统计，并代理当前主帖的点赞控件，评论区与完整播放器仍保留在原站。小红书适配 `/explore` 发现页及内容频道，以及形如 `/explore/<note-id>` 的笔记详情；详情展示标题、正文、完整画廊、视频与互动统计，并代理当前笔记的喜欢和收藏控件，评论区仍保留在原站。Reddit 适配首页、排序页和社区 Feed；详情页与广告卡片不接管，无法稳定代理的互动通过原文链接回退。

微博与知乎 Feed 均支持直接提交原站内容检索，并在 OneFeed 中继续阅读由原站返回且具有可靠永久链接的内容结果；检索不会使用本地已加载条目替代原站查询。

扩展界面支持英文与简体中文，并自动跟随 Chrome 的界面语言；其他尚未提供翻译的语言默认使用英文。
